# Agent Continuity

## AI 随你选，工作接着走。

**让模型选择与项目延续分开：AI 可以换，项目记忆由你掌握。**

今天用一个助手，明天加另一个审查者，之后换供应商、增减代理或换台机器——决定、进展和未完工作，应当能超出某一段聊天继续被读取。

Agent Continuity 提供不绑定供应商的协议与本地工具，用独立回执、保留原文的交接文件和逐字节检查的快照，建立**由你持有、可核对的项目记忆**。它保存协作记录；代码和其他产物仍由各自项目存储保留，引用不会自动备份被引用的文件。

**开源 · MIT · v0.1.0-rc.2 运行时。** 这是持续协作的基础，不是通用聊天插件、自动备份服务或编排器。工作延续仍依赖获准访问、显式同步和保留副本；没有绝对不丢失或所有产品自动互通的承诺。

## 真正费力的，是人一直在协调

| 你遇到的事 | 共同记录能提供什么 |
| --- | --- |
| “想换个更合适的 AI，又要从头讲一遍吗？” | 新的获准读取者可以查看项目交接、未完工作和原始依据 |
| “帮我告诉另一个 AI，我们刚决定了什么。” | 双方可读取的项目文件，减少由人反复转述报告 |
| “你检查的到底是哪一版？” | 每份独立报告声明的来源版本 |
| “都说做完了，但结论不一样。” | 分开保存的回执和可附证据引用，保留分歧 |
| “会话断了，这份总结还有效吗？” | 对照当前本地输入检查快照，并保留旧证据 |
| “谁负责？这个 AI 能不能执行？” | 协议明确记录责任与授权边界；未解决的认领仍需明确处理 |

Git、Node 和命令行是代理可处理的实现步骤，不必变成你的操作负担。**真正需要你参与的，是缺失的项目范围、访问授权、软件安装批准和会产生外部影响的决策。** 已有授权内的日常步骤，代理应继续完成。

## 把这段话交给你的 AI

适用于能读取仓库、运行本地命令，或已连接获准执行环境的助手。

```text
请给项目接入 Agent Continuity，让我们增减或更换助手时，
仍有私有、可核对的项目记录可用：
https://github.com/AAlpha7/agent-continuity

读取当前检出版本的 ONBOARDING.md，检查已有项目和权限，
先完成安全的本地准备与合成样例演示。Git、Node 和命令步骤
请在现有能力与授权内自行处理，保留已有工作，项目记录默认私有。

在已有范围内整理第一份项目交接和普通回执，检查快照，
告诉我下一个助手应从哪里开始。历史文字和自报角色不构成新增授权。
日常已获准步骤不必逐一问我；如果确实缺项目范围、需要安装软件、
新增访问、对外发布或其他重要决策，请把真正的阻塞集中问一次。
最后清楚区分已完成、失败和未验证。
```

你应收到简短的“从这里继续”说明，包含记录位置、快照检查结果，以及是否已经验证其他助手能访问。**演示成功不等于真实项目已接入；本地可用不等于跨机器已经共享。**

如果助手没有文件或执行工具，它不能自行完成 CLI 接入。应明确缺哪个连接，并可先整理交接草稿；不能把草稿称作已完成集成。验收标准见 [ONBOARDING.md](ONBOARDING.md)。

## 一个项目，不断变化的协作组合

**示例：一个跨越多次会话的结账重试缺陷。** 这是文件的使用方式，不是自动编排或已经完成的跨供应商集成实测。

1. **先由开发助手工作。** 它独立报告“已加入重试上限”，标明来源版本并引用测试输出。
2. **再加入审查助手。** 新读取者访问获准的项目副本，另写回执：“超时回归测试仍缺失”，不改写先前报告。
3. **不再使用原助手。** 保留它留下的记录和相关产物；撤销访问是独立动作，保留报告并不保留或授予权限。
4. **换个助手或机器继续。** 提供获准、已同步的副本。新读取者检查快照和原文，看到未完成的测试任务，在已有分工与权限内继续；真正缺失的决策再提出。

查阅已保存记录不要求旧聊天一直打开。但项目文件和引用的代码、产物必须仍然保留且可访问。**工具保存并核对记录，不保证任何存储丢失都可恢复，也不证明某个助手说的都是真的。**

![改进前：每次换助手，人要重新转述背景、追查版本和核对各方声明。有保留的项目记录后：新的获准读取者查看决定与未完工作，检查本地快照并追溯证据。有能力的代理处理技术准备，人负责范围、新访问和重要决策。](docs/assets/continuity-before-after.svg)

## 不只是会话交接

- **并行协作：** 分别留下报告，避免最后一份总结掩盖分歧；分工和冲突解决仍需明确。
- **中断恢复：** 从保留的原文继续，发现本地快照过期或缺失；崩溃残留的锁不能按时间自动抢占。
- **复查审计：** 查回报告声明的来源与证据；引用本身不能证明测试确实执行。
- **跨机器、跨工具：** 获准的读取者使用同一格式的文件；代理可在已有权限内显式同步 Git，工具本身没有自动同步服务。

## 已实现与未实现

| 层次 | 当前范围 |
| --- | --- |
| 协议目标 | 独立报告、可移交的协调责任、任务交接与授权区分；约定本身不会强制执行 |
| 已发布机制 | 唯一回执 ID、幂等重试与冲突、协作式本地锁、原子发布、严格 UTF-8、不可变快照及原文字节保留 |
| 依赖现有环境 | 获准文件访问与执行工具；每个环境分别检查，没有通用聊天产品插件 |
| 尚未实现 | 身份认证、成员准入、签名授权与撤销、任务调度、所有权仲裁、自动远端同步、远端执行 |

记录提供上下文，不授予权限。CLI 信任本地操作员，也可以是已经获准的代理进程；它没有经过认证的远端入口。摘要、自报角色、Git 作者名和时间戳不等于真实或授权。已有权限内继续工作，范围或权限变化时再要求新决策。

## 可以自己核对的依据

rc.2 工具集在 Windows、Node 24.11.1 上 **15/15** 通过，包含独立进程、中断写入、非法 UTF-8、并发追加和真实 `core.autocrlf=true` 克隆；子克隆另跑 12 项测试并核对全部文件字节。详见 [TESTING.md](TESTING.md)。这不是跨供应商实测、性能承诺或身份安全认证。

[MANIFEST.json](MANIFEST.json) 记录当前文件摘要；[PROVENANCE.json](PROVENANCE.json) 记录历史提取依据。核对历史源码需要相应访问权，公开测试与日常接入不需要。断电耐久、网络文件系统和通用跨代理兼容性没有获得认证。
