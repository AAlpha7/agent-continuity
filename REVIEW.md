# REVIEW.md — agent-continuity

For any reviewer, human or agent, of a pull request in this repo. Keep reviews short. The goal is to catch what would hurt an adopter, not to polish prose.

Past misses to check every diff against: [`docs/review/REGRESSION_CASES.md`](docs/review/REGRESSION_CASES.md).

## What failure looks like here

This repo is mostly docs that agents follow as instructions, plus shell and Node checks. A defect here is an adopter's agent doing the wrong thing. That usually means one of these:

1. **The copied protocol breaks inside a ledger.** `PROTOCOL.md` is byte-copied into every adopter ledger as `docs/PROTOCOL.md` (`CLAUDE.md:14`). Any relative link in it, or in the other copied files, is dead inside a ledger. That shipped once (#9, fixed in #10). The prose pointer at `PROTOCOL.md:15` is not a link, on purpose. Changing `PROTOCOL.md` at all needs the task to say so and a callout in the PR.
2. **Setup writes or pushes before it has checked the destination**: owner, private visibility, effective fetch URL and all push URLs (`ONBOARDING.md:70`, `ONBOARDING.md:83`). Fixed in #12. A reorder of the Setup steps can bring it back.
3. **The docs lie.** A step names the wrong commit, file, test count or product surface. Examples: the revision line must name the commit the bytes were copied from (`ONBOARDING.md:76`, `templates/HOW_WE_COORDINATE.md:20`), fixed in #10. A single product's settings were written as if they were the only user-level surface (#13, replaced by #14). Check every number and path the diff states against the tree.
4. **`MANIFEST.json` stops matching the tree.** `test/manifests.test.mjs:10-16` requires every file to be listed exactly once with its size and SHA-256. Any added, removed or edited file means a regenerated manifest. The shell smoke only checks the rows that are listed (`scripts/ledger-smoke.sh:166-221`), so it cannot catch a missing row.
5. **Something optional becomes an adopter gate.** Node, the smoke, the two-agent check and the coordination-patterns appendix are optional (#2, #3, #4, #11). A Setup or Join paste block that starts to require one of them is a regression.
6. **Private data leaks into this public repo**: private ledger URLs, agent or session ids, private commit ids, local paths, tokens. #12 and #14 both ran an explicit leak check. Every diff needs one.
7. **The two READMEs drift.** `README.md` and `README.zh-CN.md` carry the same Setup and Join content (#1, #13, #14). An edit to one needs the same edit to the other.

## How to comment

- **Evidence or it didn't happen.** Every comment cites `path:line`, in the tree or the diff, plus what is wrong there. Don't guess from a file or function name. If you can't point at a line, don't post it.
- **Label each comment** `Important`, `Nit` or `Pre-existing`. Pre-existing means the PR didn't introduce it; say so, so it isn't charged to the author.
- **Two nits at most per review.** Drop any others. Style, wording and formatting alone are not findings unless they make an instruction wrong or ambiguous.
- **Flag the class, not just the instance.** Example: "dead relative link in a copied file". Ask for every instance to be fixed, not only the line you saw.
- **Don't repeat a finding** that is already posted on the PR. After the second round, review only the new diff.

## Summary format

The first line is the count, for example `3 issues (1 Important, 1 Nit, 1 Pre-existing)`. Then one line per issue with `path:line`.

When there is nothing to fix, write exactly `0 issues. Nothing to fix.` and stop. Don't add praise or optional suggestions.

## Paths to skip, or check mechanically only

| Path | Why | What to check instead |
|---|---|---|
| `MANIFEST.json`, `r2/MANIFEST.json` | Generated byte inventory | `node --test test/manifests.test.mjs` passes; don't read the hashes by eye |
| `docs/assets/*.png`, `docs/assets/*.svg` | Binary or generated art | Only that `docs/assets/ATTRIBUTION.md` covers any new asset |
| `fixtures/**` | Synthetic test data with hash-named files | Touched only alongside a test change that explains it |
| `PROVENANCE.json`, `SCAN-REPORT.json` | Historical extraction records | Should not change; flag it if they do |
| `History/*.md` | Dated append-only notes | Leak check only (failure mode 6) |

There is no lockfile and no vendored code: `package.json` has empty `dependencies` and `devDependencies`.

## Checks to run, and quote, before approving

- `sh scripts/ledger-smoke.sh` ends with `ledger-smoke: ok` and the `manifest: N HEAD blobs match MANIFEST.json` line.
- `node --test test/*.test.mjs r2/test/*.test.mjs` on Node.js 24 or later (`package.json` `engines`). A run on an older Node is not evidence (#13 hit 4 rename-retry failures on Node 22 that were unrelated to its diff).
- `scripts/ledger-smoke.ps1` changed but never ran: say so as a gap, don't count it as a pass (#7, #9, #10).
- Never accept skipped hooks (`--no-verify`) or a disabled secret scan. Hosted CI is not configured, so "no checks failed" proves nothing.
